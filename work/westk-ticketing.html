01 / PROJECT OVERVIEW

统一入口背后，
是一个多业务票务系统。

项目需要承载演出、展览、活动、会员与联票等多类型商品，并贯通从内容发现到电子票核验的完整链路。

设计的重点不是单个页面是否好看，而是如何让日期、场次、票种、价格区域、座位、实名信息、优惠、配送与售后规则在不同场景中保持一致，同时兼顾桌面端与移动端浏览。

页面中的演出信息、图片和业务数据为设计稿示意内容，部分信息已脱敏。

02 / DESIGN CHALLENGE

把复杂规则放在后台，
把明确选择留给用户。

票务产品的复杂度来自大量条件组合。设计需要在用户决策过程中逐步呈现信息，而不是一次性暴露全部规则。

01

多类型项目

展览、演出、活动、联票和会员卡拥有不同的售卖逻辑、有效期与入场规则。

02

长链路购票

日期、场次、票种、座位、实名、优惠、配送和支付，每一步都可能产生状态分支。

03

购后服务

电子票、转赠、改签、退款和会员激活需要与原订单保持可追溯的一致体验。

03 / EXPERIENCE MAP

围绕一次完整观演旅程，
重组票务体验。

从“发现内容”开始，到“持票入场”和“售后处理”结束，页面结构与状态反馈都围绕用户当前任务展开。

01

CONTENT DISCOVERY

让用户先看到值得参与的内容，
再进入购票决策。

首页通过主推荐、即将开售、活动列表和日历入口组织内容。桌面端强调横向浏览效率，移动端则将内容转为连续卡片流，保持活动类型、日期、地点和价格信息的识别顺序。

点击页面可查看完整设计稿
主次分层

首屏聚焦当前重点项目，避免活动信息在同一层级竞争注意力。

快速扫读

卡片固定呈现类型、日期、场地与起售价，支持快速比较。

响应式重组

移动端不是等比缩放，而是重排信息并减少横向依赖。

02

EVENT DECISION

项目详情页同时承担内容阅读与购票转化。

页面将主视觉、价格、日期、场地、服务保障与优惠信息集中在首屏。右侧购买摘要保持稳定位置，让用户阅读项目介绍时随时可以继续购买。

  • 01
    核心信息前置

    价格、场地、日期和可售场次无需滚动即可确认。

  • 02
    可信信息可见

    出票方式、电子发票、选座与退款规则明确展示。

  • 03
    推荐形成闭环

    详情末尾延续同类活动推荐，降低浏览中断。

03

TICKETING ENGINE

通过渐进式选择，
管理日期、场次、票种与座位。

把选择过程拆成稳定的步骤，并在右侧持续反馈已选内容、价格和异常状态。用户不需要理解后台规则，只需完成当前一步。

DATE

日期与场次联动

可售、即将售罄与售罄状态使用文字和颜色共同表达。

PRICE

价格区域可追踪

价格颜色贯穿筛选、座位图与订单摘要，降低映射成本。

ACCESS

无障碍席位纳入主流程

轮椅座、遮挡座等特殊属性直接进入座位选择和结算信息。

SUMMARY

选择结果即时反馈

右侧摘要同步展示票数、座位、票种与小计，减少回退确认。

04

CHECKOUT

结算页把复杂条件转化为可检查的任务清单。

订单明细、优惠、联系信息、出票方式、配送地址、附加偏好、捐赠与支付被拆成独立区块。固定摘要持续显示费用变化，避免用户在长表单中失去方向。

价格透明

优惠、服务费和总价逐项显示。

配送灵活

电子票、现场领取与快递动态切换。

时间提醒

锁座倒计时与错误状态保持可见。

05

TICKET OWNERSHIP

支付完成不是终点，
票夹才是服务入口。

用户可以在统一票夹查看项目、座位、二维码与转赠状态。电子票与订单详情使用一致的信息层级，让“查看、使用、转赠”成为自然连续的动作。

06

BUSINESS EXTENSIONS

在主购票链路之外，
建立会员与联票的统一表达。

平台不仅销售单场门票，还需要承载跨场馆会员卡、家庭卡、联票组合与优惠权益。通过复用卡片、价格、状态和摘要结构，减少新业务对用户学习成本的影响。

07

AFTER-SALES SERVICE

让改签与退款保持可控、可追溯。

售后流程延续原订单结构：先选择可操作票券，再确认新场次或退款规则，最后提供清晰结果反馈。复杂条件通过分步页面呈现，降低误操作风险。

04 / DESIGN PRINCIPLES

贯穿全链路的四个设计原则。

页面数量很多，但用户感知到的应该是一套稳定、可预测的系统，而不是分散的功能集合。

01

渐进式披露

只在当前步骤展示必要规则，避免用户一次面对所有业务条件。

Progressive Disclosure
02

状态双重表达

颜色与文字标签同时描述可售、售罄、优惠、异常和特殊席位。

Accessible States
03

摘要持续可见

在选择和结算阶段持续同步订单内容与金额，降低记忆负担。

Persistent Summary
04

模块跨业务复用

活动、联票和会员共享卡片、标签、价格与操作语言，保证扩展性。

Scalable System
05 / SELECTED CORE SCREENS

CORE PAGE COLLECTION

精选核心页面，
完整串联购票体验。

从完整项目素材中精选 27 个核心页面，覆盖登录、首页、活动浏览、活动详情、购票、选座、购物车、订单、支付、会员卡、个人中心与联票等主要场景。每个关键环节仅保留一至两个代表页面，便于快速了解系统结构与体验闭环。

点击任意页面可查看大图，并使用方向键连续浏览。

本合集只展示主要业务路径中的代表页面，异常状态、边界条件与大量组件状态已从公开页面中精简。

PROJECT SUMMARY

从“购买一张票”，
延伸为完整的文化参与体验。

本项目覆盖内容发现、项目决策、选票选座、实名校验、优惠与支付、电子票、会员、联票、转赠、改签和退款等场景。设计通过稳定的信息结构和组件语言，把不同业务规则收敛为一套可持续扩展的购票体验。
