# 西岸小梦：从一句问询，到一段美好体验

## 设计定位

基于现有微信小程序智能客服界面进行体验迭代。面向到访西岸梦中心的城市休闲用户，覆盖出行、餐饮、活动、亲子规划、会员、服务反馈，以及新增的酒店和景点票务。

保留紫色与小梦人物识别。设计变化集中于信息层级、状态反馈、操作路径和可信表达。作品集采用浅色编辑式布局，产品界面采用低噪音对话布局。视觉变化强度 6/10、动效 2/10、内容密度 4/10；动效只用于响应反馈与滚动定位。

## 原稿审视

- 首页：连续横排提问词条有截断，欢迎语和营销卡争夺注意力。改为任务分组与轻量灵感卡。
- 停车：先展示总车位表，后用长段落补充实际余位，信息重复。改为余位结论、三项比较和直接路线入口。
- 会员：直接断定身份与车型。改为先确认演示身份，再呈现额度与规则。
- 活动：免费与买票动作存在表达不一致，今天与周末语境混合。改为固定日期示例、兴趣筛选和费用明确的详情。
- 行程：长时间轴底部被输入框覆盖，且缺少修改机制。改为独立滚动区域、局部替换和雨天分支。
- 投诉：安慰与优惠券代替问题处理。改为同理回应、可编辑摘要、明确提交与工单状态。

## 表达层设计

| 用户任务 | 主要表达 | 配合表达 | 使用理由 |
| --- | --- | --- | --- |
| 提出模糊需求 | LUI 自然语言 | 快捷问题 | 降低表达门槛 |
| 补充关键条件 | 多轮追问 | 筹码与表单 | 每轮只补齐必要信息 |
| 比较选项 | GUI 卡片 | 简短推荐依据 | 保持同维度比较 |
| 理解空间 | 地图示意 | 入口、方式、距离 | 直观表达位置关系 |
| 规划时间 | 时间轴与行程单 | 日期、偏好和调整按钮 | 看清次序与约束 |
| 预订确认 | 摘要与确认单 | 退改说明、合计价格 | 精确信息由用户复核 |
| 追踪服务 | 状态时间轴 | 人工入口、结果反馈 | 降低处理过程的不确定感 |

## 完整情景脚本

### 1. 停车到达

用户：“现在去西岸梦中心还有车位吗？”

小梦：“目前有 447 个空闲车位。优先看看 P1，余位较多，停车后去滨江也方便。”

界面：P1 / P2 / P3 剩余车位、每小时参考费用、充电标记、路线入口；时间标注为演示快照。

用户：“我今天停车免费吗？”

小梦：“先确认你的会员身份，我再帮你看今天可用的停车减免。”

用户选择金卡 → 权益卡显示 4 小时今日可用额度。用户选择非会员 → 展示收费参考与 P1 路线入口。

用户：“停 5 小时要多少钱？”

界面：输入停留时长，按示例口径计算 `max(0, ceil(时长) - 4) × 6`。支持 1–24 小时范围校验。

用户选择 P1 → 可点击地图标记切换 P1/P2/P3 → 选择驾车/步行 → 路线预览 → 模拟到达 → 餐饮或活动下一步。

设计解析：用户体验上减少从长文寻找答案的成本；交互上将比较、选择与路线连接；产品上连接停车和会员能力，同时保留数据时效边界。

### 2. 美食优惠

用户：“中午想吃点好的，有什么推荐？”

小梦：“今天几位一起用餐，有没有口味偏好？”

用户：“4 人，想吃重庆火锅。”

小梦：“4 人聚餐，推荐这份火锅套餐。支持到店选鸳鸯锅，辣度可再和门店确认。”

界面：四人餐、参考价格、门店图片、套餐详情、优惠券。可改选两人清淡餐；未明确偏好时可先看两类推荐。

用户领取优惠券 → 状态改为已领取 → 再次点击查看规则与本地保存说明。

用户查看套餐 → 查看到店路线 → 可继续规划餐后行程。

设计解析：人数和口味先于商品；商品卡负责比较与操作，对话负责解释推荐依据；优惠不会替用户自动核销或下单。

### 3. 活动探索

用户：“这周末西岸有什么有意思的活动？”

小梦：“先按时间帮你排好了。可以切换日期，或只看你喜欢的类型。”

界面：2026 年 7 月 25/26 日情景，全部/音乐/亲子/艺术筛选，时间轴。

用户选择音乐 → 免费水岸音乐会详情 → 查看路线或加入行程。

用户选择亲子 → 活动详情 → 场次与人数 → 合计金额 → 确认模拟预约 → 明确非有效门票的结果卡。

设计解析：日历负责定位时间，卡片负责理解活动，确认单负责行动；免费与付费项目使用不同主动作。

### 4. 亲子与双人行程

用户：“带孩子来西岸，帮我安排半天吧。”

小梦：“你准备和谁一起，逛多久？”

亲子选项：带 6 岁孩子玩半天 → 13:00–17:00 的停车、午餐、探索与散步安排。

双人选项：两人轻松逛三小时 → 14:00–17:00 的停车、咖啡、艺术空间与散步安排。

用户：“下雨了。” → 替换户外站点为室内艺术空间与书店；保留其他约束。

用户可将午餐换为咖啡休息 → 保存当前行程 → 导出文本。在其他场景加入的活动、酒店和门票作为附加预订显示，并保留各自日期，避免跨日期自动拼接。

设计解析：清晰展现同行人与时长；局部修改避免重做全程；行程保存与真实服务预约分开表述。

### 5. 会员权益

用户：“我今天停车免费吗？”

小梦：“是否减免取决于会员身份和今日剩余额度。先选择一个演示身份吧。”

选择金卡 → 会员卡、今日额度、抵扣前提；选择非会员 → 原价说明。

用户可试算超时费用，查看权益规则，直接进入停车路线。

设计解析：身份不是系统凭空推断；总权益与当前可用额度分离；每个结论都对应条件与下一步。

### 6. 服务反馈

用户：“船坞附近洗手间地面湿滑，洗手池也堵住了，希望尽快处理。”

小梦：“抱歉让你和孩子遇到这样的情况。地面湿滑需要优先处理，请先避开积水区域。我把问题整理好了，确认后再提交给服务团队。”

界面：可编辑位置与问题描述，未填写时不可提交，明确模拟提交。

用户确认 → 工单编号 → 已记录 → 等待处理。

用户查看后续模拟进度 → 清理与维修 → 复查 → 用户确认已解决，或继续反馈未解决。全过程保留人工入口。

设计解析：先照顾当下处境，再建立可跟进对象；不以优惠补偿替代解决问题；工单状态以可见、可追踪的方式减少重复描述。

### 7. 酒店推荐与预订

用户：“在西岸附近住一晚，有什么合适的酒店？”

小梦：“先告诉我入住时间、同行人数和预算，我再帮你比较。”

界面：入住/离店日期、成人/儿童组合、每晚预算、江景/亲子/预算偏好。离店日期必须晚于入住日期。

用户：“10 月 1 日到 2 日，2 位成人，每晚 800 以内，江景优先。”

界面：3 家虚构示例酒店（江景 ¥688、亲子 ¥568、预算 ¥398），展示位置距离、床型、早餐、每晚价与全程含税参考总价。

选择亲子人数时过滤为适合 2 大 1 小的家庭房；预算不足时展示无匹配结果，并保留修改条件入口。

用户选择房型 → 查看床型、早餐、日期、晚数、房间数、退改规则 → 核对订单 → 勾选已阅读示例规则 → 确认模拟预订。

结果：模拟订单编号、房型、日期、总价、非真实入住凭证；可加入行程或确认取消演示订单。

设计解析：LUI 负责需求说明，表单负责日期与人数准确性，比较卡负责挑选，确认单负责责任边界。价格必须关联日期、晚数与入住条件；不在原型中索要真实证件信息。

### 8. 景点票务预订

用户：“想订游船或者看展的门票，有什么推荐？”

小梦：“这三类票务可以直接比较，选好后再确认日期与票种。”

示例：黄浦江滨江游船、西岸当代艺术展、滨江亲子探索；分别展示游玩类型、时长与成人参考起价。

选择项目 → 日期 → 场次 → 成人票或亲子票 → 数量 → 总价实时变化。

亲子票显示 1 大 1 小、儿童年龄示例条件。两份游船亲子票：192 × 2 = 384 元，合计 4 人。

下一步：核对日期、时间、票种、份数、人数、总价与退改 → 阅读确认 → 模拟预订成功 → 加入行程/取消。

设计解析：对话用于推荐，GUI 用于精确选择；份数与人数同时呈现，减少亲子套餐误解；支付与出票未接入时，结果不可伪装为真实电子票。

## 手机内弹层规范

所有弹窗由统一的 `sheet()` 入口创建，嵌套在 `.phone` 内。遮罩层使用手机容器的绝对定位，底部弹层宽度随手机内容区变化，不使用浏览器顶层 `showModal()`。路线、优惠规则、费用试算、酒店房型、票种选择、订单确认、人工说明、语音示例和菜单共享这一实现。

- 弹层顶部预留空间，底部兼顾手机安全区；标题与关闭按钮固定，正文独立滚动。
- 打开时手机内的底层内容设置为 inert，键盘焦点在弹层内循环。
- 点击关闭、点击遮罩或按 Escape 返回；恢复触发控件焦点，保留对话滚动位置。
- 桌面手机框根据浏览器高度缩放可视高度；手机全屏时宽度与视口一致。
- 已验证 1280×720 桌面和 375×812 手机下弹层边界均处于手机内；长票务表单滚动发生在弹层正文。
